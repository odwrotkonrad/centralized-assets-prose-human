# Conventions

- `conventions/purpose/convention.md`: every repo's purpose doc, three headings (what, why, goals), authored in `cross-repo/prose/assets` (`repos/<repo-path>/purpose.md`), rendered into the repo as gitignored `assets/docs-agents/purpose.md`, included at the top of `AGENTS.md`, `CLAUDE.md`, `README.md`.
- `conventions/comments/convention.md`: comment label prefixes (`[where]`, `[why]`, `[what]`), `[>]`/`[<]` sectioning, 🤖 AI-generated marks.
- `conventions/makefile/convention.md`: house Makefile style, `[genai-include]` sectioning that feeds the generated Makefile doc for AI agents.
- `conventions/templates/convention.md`: repo docs generated with che templates from the prose repos at pinned versions: `cross-repo/prose/assets` at `PROSE_ASSETS_REF` (`@gitlab.com/konradodwrot/cross-repo/prose/assets//<path>?ref=$PROSE_ASSETS_REF`), `cross-repo/misc` at `MISC_REF` (CI scripts), one `GRP_KO_VAR_<PIN>` group variable each, seeded into `.env` locally. `cross-repo/prose/spec` renders into no repo: `ai-harness/configs` `base` renders this summary once onto the host at `PROSE_SPEC_REF`, `~/.config/claude/CLAUDE.md` and `~/.config/codex/AGENTS.md` `@`-include it. `AGENTS.md`, `CLAUDE.md` and intermediates gitignored, `README.md` and `LICENSE` rendered and tracked. `make render-templates`.
- `conventions/ci/convention.md`: lefthook pre-commit hooks (minimal: docs generation check), re-run in a minimal CI validate job. Every job image pulled from Artifact Registry, never a public registry.
- `conventions/ci-variables/convention.md`: every GitLab CI/CD variable carries a scope prefix, `GRP_<MNEMONIC>_VAR_` for group-level (`GRP_KO_VAR_` for `konradodwrot`), `REPO_VAR_` for project-level (the repo unnamed: the scope already names it). A variable carrying a credential names its protection too, `REPO_PROTECTED_VAR_`, `REPO_UNPROTECTED_VAR_`, `GRP_KO_PROTECTED_VAR_`, with `BOT` marking a GitLab access token specifically. Non-secret variables are declared in `cross-repo/infra/ci-variables`, secrets and identity variables in `cross-repo/infra/base`, never clicked into the UI. Each pipeline remaps every injected variable it consumes to the bare name once, at the boundary (group vars in the top-level `variables:` block, project secrets on their job). Jobs, scripts and tools read only bare names. The bare name is never defined in GitLab. A tracked `.env.tpl` at the repo root, the one template che renders to `.env` (plain values, 1Password `secret` refs, `glab variable get` shell calls), carries the same bare names for local runs.
- `conventions/dev-env/convention.md`: every repo exposes `repo-prepare-dev-env`, a wrapper chaining render, dependencies, then hooks (that order: the docsgen hook renders, so hooks installed before the first render fail a fresh clone's first commit). A repo declares its toolchain in a `devEnv` che profile instead of assuming the host has it. `repo-prepare-deps` installs that toolchain plus the project dependencies it manages, into the checkout, without root. `cross-repo/automation`'s workspace profile runs it over every cloned repo, between cloning and indexing.
- `conventions/license/convention.md`: every public repo carries `LICENSE` (unmodified MIT), rendered from the canonical `cross-repo/prose/assets` `shared/license/LICENSE`.
- `conventions/spec-scenarios/convention.md`: behavior specs as markdown feature files, all in `cross-repo/prose/spec` (`repos/<repo-path>/spec/`), edited there before implementing in the repo. Two forms sharing a stem in the unit dir: `<feature>.story.md` (user stories, the default: H2 `As a <role>`, H3 story title, `I want` / `so that`) and `<feature>.scenarios.md` (Gherkin scenarios, only for automation-bound behavior). Each story and scenario title closes with its status (`todo | implemented | tested`), kept accurate, and states the value for its audience. Vetting dirs: `vetted/` (AI never touches), `vetted_title_only/` (story titles and `Scenario:` lines frozen, rest editable), `unvetted_ai/` (AI free rein, new AI specs land here). Moves between dirs come from human will. `technical-requirements.md` uses the same dirs, prefer `vetted/`: on add or change, AI urges vetting first.
- `conventions/claude-agents/convention.md`: per-repo `RO-<Repo>`/`RW-<Repo>` claude agents, che-rendered into `.claude/` on virt only. Shared snippets served from `ai-harness/configs` (authored in `cross-repo/prose/assets`), consumed via one remote profile include plus `ctx`. Rendered outputs never committed.

Each convention dir carries a runnable `example/`. This repo follows all of them.
