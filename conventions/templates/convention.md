# Templates Convention

Repo docs are generated: che renders `*.ontoRepo.tpl` onto the repo. Generated files carry an autogenerated header and are never edited directly. Edit the template, re-render.

## Layout

- Doc templates are authored in `cross-repo/prose/assets`: shared `2-data` templates under `templates/2-data/`, per-repo `3-audience` templates under `repos/<repo-path>/templates/3-audience/`. A repo keeps locally only the repo-specific: `.env.tpl` at the root (the one env template, rendered to `.env`: plain values, `{{ secret "op://..." }}`, `{{ shell "glab variable get ..." }}`) and code-generating templates (CI includes, terraform files).
- Every remote source in a `che.yml` carries a ref: `git::<repo>@${{ env.<NAME>_REF }}//<path>`. An omitted `@<ref>` resolves to default-branch HEAD, so an unpinned source silently tracks another repo's `main` and a render stops being reproducible. One pin per producer consumed: `PROSE_ASSETS_REF` (purpose docs, templates, license), `MISC_REF` (shared CI scripts), `PROSE_SPEC_REF` (conventions summary, `ai-harness/configs` only), `CONFIGS_REF` (the base profiles the sandbox image builds from), `AI_CONFIGS_REF` (the AI harness profiles: `claude/virt` and the `ai/*` area aggregates), `AUTOMATION_REF` (the `workspace` profile, `configs` only), `IAC_REF` (the terraform lock, `oci-images` only). Every pin is held in the repo's tracked `.repo/upstream.env` lockfile, which `.env.tpl` pulls into `.env` wholesale (`{{ localFile ".repo/upstream.env" | alwaysUpdate }}`, `make repo-render-env`) and `render-templates.zsh` exports before the dev render, so a stale pin in the shell cannot downgrade a generated doc. CI is the other way round: a pipeline renders at its job variables, derived in the top-level `variables:` block from `GRP_KO_VAR_<PIN>`, and automation's regen MRs are what carry a moved group variable into the lockfile line.
- `cross-repo/prose/spec` renders into no repo. The conventions summary loads once onto the host: `ai-harness/configs` `base` renders `@${{ env.PROSE_SPEC_REF }}//conventions/conventions.md` to `~/.config/ai-agents/docs/conventions.md`, `@`-included by `~/.config/claude/CLAUDE.md` and `~/.config/codex/AGENTS.md` beside `system.md`, `code.md`, `comments.md`, `prose.md`. `ai-harness/configs` is the sole `PROSE_SPEC_REF` consumer.
- Generated data docs land in `assets/data/`, `@`-included in `CLAUDE.md` and `AGENTS.md`: `makefile.agents.md` (`renderMakefileDoc`), `repo-structure.md` (`renderDirsTree`), `assets/docs-agents/purpose.md` (rendered from its prose source).
- `CLAUDE.md` and `AGENTS.md` render from one `3-audience/AGENTS.md.ontoRepo.tpl`: `CLAUDE.md` keeps `@`-includes, `AGENTS.md` inlines them (`renderReferencedFiles: true`) for agents that do not resolve `@`.
- `AGENTS.md`, `CLAUDE.md` and the `assets/data/` + `assets/docs-agents/` intermediates are gitignored: rendered on demand, never committed. `README.md` and `LICENSE` are rendered and tracked: forges read them from the repo.

## Example

Runnable version in `example/`: `che.yml`, `Makefile`, `.env.tpl`, the `2-data` and `3-audience` subdirs, generated `assets/data/makefile.agents.md`, `CLAUDE.md`, `AGENTS.md`. `.env` renders from `.env.tpl`, never committed. The example uses local template sources to stay self-contained. Real repos pull the same templates from `cross-repo/prose/assets` at a pinned ref.

## Wiring

`che.yml` maps each template source to its dest paths under one `renderTemplates:` key, see `example/che.yml`. The dest path picks the target: relative renders into the repo, `~/` or absolute onto the host. Template extensions are informational: `*.ontoRepo.tpl` (repo dests), `*.ontoHost.tpl` (host dests), bare `*.tpl`. Repo-doc entries live in one `ontoRepo` profile with `options: {autoDiscover: true}`. Profiles default to `autoDiscover: false` and run only when named via `--profile`. The Makefile `render-templates` target runs `che render-templates`.

## Authoring

- Prefer gomplate built-ins over custom plugins or scripts.
- che funcs cover repo docs: `renderMakefileDoc "Makefile"` harvests `[genai-include]` Makefile sections, `renderDirsTree` emits the tracked-file tree for `repo-structure.md`, `renderRepoGroupIndex "<dir>"` emits a subgroup's repo-index (direct child repos with inlined purpose, direct child subgroups linked to their own index) for `repo-index.md`.
- `remoteFile "git::gitlab.com/konradodwrot/cross-repo/prose/assets@v0.0.1//shared/license/LICENSE"` inlines a file from any git repo at render time. A prose source builds its ref from the env: `remoteFile (printf "git::gitlab.com/konradodwrot/cross-repo/prose/assets@%s//<path>" (env.Getenv "PROSE_ASSETS_REF"))`. One go-getter style string: `git::<repo>[@<ref>]//<path>`, default branch when `@<ref>` is omitted, https first, ssh-agent fallback for private repos. `remoteFile` output is inserted verbatim, never re-evaluated. A gomplate-bearing upstream file that must land intact is not wrapped in a template: a remote `makeCopies` leaf (`git::<repo>@<ref>//<path>`, explicit dest) copies the bytes as-is.
- Every template file ends in `.tpl` as its last extension (`AGENTS.md.ontoRepo.tpl`, `git-commit-msg-suggest.md.tpl`), never `.tmpl` or a `.tpl` buried mid-name.
- `op://` secret refs and `shell` calls resolve at render time (`.env.tpl`). Never commit resolved values.
- Under `writeType: mergeUpsert` a value decides whether it overwrites the dest's existing key: `shell` and `secret` values update by default, everything else keeps, `| alwaysUpdate` / `| keepIfExisting` after the expression overrides per line.
